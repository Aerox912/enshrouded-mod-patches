# Optional Vein Mining activation modes

Original mod: XHL's Vein Mining 1.0.33, https://www.nexusmods.com/enshrouded/mods/129.
The input helper and its source are by Aerox912 and licensed under the repository's MIT license. It does not replace or relicense the original mod.

The next Mod Manager exposes Hold, Toggle and Always on in Settings > Hotkeys. New installations and updates rewrite the activation preset to Toggle, as requested. Existing activation keys and the saved radius are preserved. Hold and Always on remain selectable afterward. Toggle suggests F8 when selected in settings, which the player can change. Always on requires no activation key. Every mode still requires the normal mining action on the controller or keyboard.

Hold keeps the original target-ore bar. Toggle and Always on hide it. Toggle shows a click-through `Vein Mining: On` or `Vein Mining: Off` notice for 1.5 seconds after a fresh activation press. Losing focus dismisses the notice.

The paired radius candidate adds F12 cycling between 1x (5 m), 2x (10 m) and 3x (15 m) in all three modes. The first launch uses 2x. Later launches restore `RadiusMultiplier` from `[VeinMining]` in `mods/XHL-Vein-Mining/radius.ini`, separate from the manager-owned activation file. A fresh F12 press shows a brief radius notice; held keys and focus changes do not repeat it. Failed preference writes retry at most once per five seconds. F12 is reserved when this extension is installed. Pickaxe reach stays at the original mod's separate 10 m setting.

In Toggle and Always on, key reads on the preview window's owning thread return inactive after sampling the shared activation state. This keeps the pinned mod's hidden target scanner and renderer idle, while its message loop still polls the hotkey and drives notices. Mining and network threads receive the normal activation state. The ownership check ends when the preview is destroyed; Hold keeps its original preview behavior.

Only the pinned Vein Mining DLL's USER32 import is redirected to vmkeys.dll, including Hold in the radius candidate. Hold activation still passes through the Windows result. The helper handles GetAsyncKeyState and four window lifecycle/display imports; other calls are forwards. Window handling is limited to the verified `XHLVeinMiningPreviewOverlay` class. The notice uses the original overlay thread's message pump and is destroyed with that overlay. It cannot take focus or intercept clicks. No game-wide keyboard hook or synthetic input is used. The three existing key reads share one serialized toggle state so mining and network requests agree. Losing focus pauses output and retains the toggle state; returning with the key already held does not toggle. A new game process starts with toggle off.

Files: vmkeys.dll belongs beside enshrouded.exe. Personal activation mode is in mods/XHL-Vein-Mining/controls.ini, [VeinMining], Mode=hold, toggle or always. Change it while the game is closed. The manager also saves the activation preference for reinstalls and profile switches. The radius candidate requires the matching client DLL and server adapter with the expanded pinned original DLL. Install the pair together. The server rejects unexpanded DLLs and old request versions; no legacy fallback is supported.

The shared `enshrouded-server-compat/src/vein_radius.cpp` hooks only the hash-verified original mod's callbacks. Paired A6 requests carry a bounded multiplier and nonce, retain the full sender ID, expire after one second, and are consumed once. Decoded serials are compared with wrap-aware ordering while the sender remains in the fixed cache; old packets and altered radius bits cannot reactivate a consumed request. Per-thread scopes restore activation and radius after a mining call. The selected radius applies to both the broad-phase sphere and exact material filter; stock payout code remains in the original module. The original per-axis 64-cell guards remain, with the per-region volume cap expanded on disk from 65,536 to 262,144 cells before loading. The three original scratch arrays use 7 bytes per cell, at most 1,835,008 bytes per region. No extra scanning or allocation occurs merely because Toggle or Always is enabled. Larger mining actions still need live performance and payout acceptance.

Build with CMake and MSVC for Windows x64, then run CTest. Tests cover hold passthrough, debouncing across repeated readers, background/focus transitions, notice expiry and the real DLL exports in all three modes. Window fixtures verify preview suppression, unchanged unrelated windows, click-through behavior and cleanup. In-game notice appearance and controller mining require a separate gameplay check.

To remove the radius extension: restore the verified non-radius original/localized Vein Mining DLL and its matching helper through the manager transaction. Radius-enabled Hold still imports vmkeys.dll, so selecting Hold alone does not allow removing the helper. Never remove the helper while a DLL still imports it.
